| Location management | Edit and archive, inactive toggle, parent-chain cycle rejection; refuse archival when children, assets, active employees or membership grants remain | `location.manage`, tenant/location management scope, audit |
| Employees | Designation/type fields, active/inactive controls, rejects deactivation while any assets remain assigned | `employee.manage`, location-scope and audit |

| Asset register | Category/model/location/warranty filters; allowlisted sorts, stable 20/page navigation | `asset.read` and location scope on server |
| Inventory numbering | Automatic `PREFIX-000001` style values from atomic tenant sequence, manual numbers retained, collisions skipped | Locked tenant subscription transaction + tenant-unique inventory number |
| Asset lifecycle | Damage, restore, dispose and retire with required reason, status checks, custody restrictions and history events | `asset.update` / `asset.dispose`, location management checks |
| Bulk assignment | Atomic handover of up to 50 available assets at the destination employee's home location | `asset.assign`, CSRF, transaction and audit |

## Additive MySQL migrations, in order

1. `20261111000100_company_preferences` — five tenant preference columns.
2. `20261111000200_account_tokens` — user-linked hashed token table.
3. `20261111000300_asset_sequences` — per-tenant inventory numbering and backfill for existing tenants.
4. `20261111000400_employee_classifications` — optional designation/type fields.

These migrations are intended to preserve users, assets, roles, transfer
histories and subscription data. **Never run `prisma migrate reset`** on
`assetmov` or customer data.

## Windows WAMP acceptance sequence

First verify the source without migrating the existing development database.

```powershell
cd C:\wamp\www\html\assetmov
git fetch origin
git switch --track origin/feature/p0-hardening-company-assets-20261111
npm ci
npm run db:validate
npm run db:generate
npm run typecheck
npm run lint
npm test
npm run build
```

Use the isolated local test database for migration and API acceptance.
A test script is intentionally refused against `assetmov` or non-local hosts.
Use `try/finally` to restore the previous environment after the suite.

```powershell
$previousDb = $env:DATABASE_URL
$previousFlag = $env:ASSETMOV_RUN_DB_INTEGRATION_TESTS
try {
    $env:DATABASE_URL = "mysql://root:@127.0.0.1:3306/assetmov_test"
    $env:ASSETMOV_RUN_DB_INTEGRATION_TESTS = "1"
    npm run db:deploy
    if ($LASTEXITCODE -ne 0) { throw "Test migration failed" }
    npm run db:seed:plans
    if ($LASTEXITCODE -ne 0) { throw "Test seeding failed" }
    npm run test:integration
    if ($LASTEXITCODE -ne 0) { throw "MySQL API acceptance failed" }
}
finally {
    if ($null -eq $previousDb) { Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue }
    else { $env:DATABASE_URL = $previousDb }
    if ($null -eq $previousFlag) { Remove-Item Env:ASSETMOV_RUN_DB_INTEGRATION_TESTS -ErrorAction SilentlyContinue }
    else { $env:ASSETMOV_RUN_DB_INTEGRATION_TESTS = $previousFlag }
}
```

**Important:** MySQL integration tests are intended to run on a disposable
`assetmov_test` database with a correct full migration history. A normal
run of `npm test` does **not** exercise these MySQL acceptance cases.

Only after tests pass and you have backed up the development `assetmov`
database should you run `npm run db:deploy` against that development DB.

## Manual browser acceptance

Use a disposable test tenant, not a real customer:

- Company Admin: open Profile, change timezone/currency and numbering prefix, reload.
- Company Admin: add/edit/archive suppliers, manufacturers and locations.
- Reject a self-parenting location and archiving a location with active custody.
- Create/edit/deactivate employee (deactivation must fail when assigned).
- Asset Register: create automatic and manual numbers, filter and paginate.
- Try duplicate inventory number; verify it is rejected without double creation.
- CSV: preview valid and invalid rows, import, retry failed rows; verify per-row
  audit trail and asset cap. Quoted CSV data must not break row parsing.
- Asset lifecycle: damage, restore, retire/dispose, check timeline and terminal
  statuses; verify no unauthorized or cross-tenant action.
- Bulk assignment: two available assets assigned atomically to same-location
  custodian; repeat/invalid/mixed location must not partially mutate.
- Transfer: print dispatch Issue Note and completed/partial GRN on A4.
- Email: configure a real verified Resend sender, run forgot/reset, confirmation,
  invitation, resend, expiry and replay checks. Only enable
  `REQUIRE_VERIFIED_EMAIL=true` **after** delivery, account onboarding and
  existing-user migration have been tested.
- Desktop/tablet/390px/mobile role-based UI, keyboard nav and different tenant
  identities (see `BROWSER_ACCEPTANCE.md`).

### Optional identity-email environment variables

In `backend/.env` (do not commit credentials):

```dotenv
EMAIL_DELIVERY_API_KEY=
EMAIL_FROM_ADDRESS=
REQUIRE_VERIFIED_EMAIL=false
```

The email adapter uses Resend; the sender must be a verified domain.
Empty keys are acceptable when email features are not being tested.
Do not enable required verification until existing accounts can verify.

## Remaining P0 gaps

This is **not a completed P0 release**. Remaining separate work includes:

- First-login onboarding and account invite deliverability/abuse monitoring on
  real email, plus account lockout policy and anti-abuse controls.

  and downloadable row-error reports.

- Complete employee location history and bulk return/reassign, movement concurrency

- Supplier/manufacturer lifecycle history UI, tenant settings onboarding wizard,
  safe archives of categories/models, last-owner recovery policy verification.
- Full browser accessibility and tenant/location matrix acceptance, including
  actual Paddle-independent subscription/expiry testing.
- Secure production file storage, default Linux MySQL migration replay and
  production risk review. Paddle sandbox and GitHub Actions checks remain
  **explicitly deferred by the owner**, not passed.

Do not merge until local Prisma validation, typecheck, lint, unit tests,
MySQL API acceptance and build pass. Review any failures on the feature branch.
