## Implemented in this branch

| Area | Change | New permissions / safety |

| Location management | Edit and archive, inactive toggle, parent-chain cycle rejection; refuse archival when children, assets, active employees or membership grants remain | `location.manage`, tenant/location management scope, audit |
| Employees | Designation/type fields, active/inactive controls, rejects deactivation while any assets remain assigned | `employee.manage`, location-scope and audit |

| Asset register | Category/model/location/warranty filters; allowlisted sorts, stable 20/page navigation | `asset.read` and location scope on server |
| Inventory numbering | Automatic `PREFIX-000001` style values from atomic tenant sequence, manual numbers retained, collisions skipped | Locked tenant subscription transaction + tenant-unique inventory number |
| Asset lifecycle | Damage, restore, dispose and retire with required reason, status checks, custody restrictions and history events | `asset.update` / `asset.dispose`, location management checks |
| Bulk assignment | Atomic handover of up to 50 available assets at the destination employee's home location | `asset.assign`, CSRF, transaction and audit |
| Transfers | Browser-printable Issue Note / GRN from a transfer's full line decisions | Uses already authorized transfer detail; no file storage |

| Email policy | Resend API adapter, optional verified-email enforcement on login and all tenant APIs | Email requirement **off by default** until outbound mail is verified |

## Windows WAMP acceptance sequence

First verify the source without migrating the existing development database.

```powershell
cd C:\wamp\www\html\assetmov
git fetch origin
git switch --track origin/feature/p0-hardening-company-assets-20261111
npm ci
npm run db:validate
npm run db:generate
npm run typecheck
npm run lint
npm test
npm run build
```

Use the isolated local test database for migration and API acceptance.
A test script is intentionally refused against `assetmov` or non-local hosts.
Use `try/finally` to restore the previous environment after the suite.

```powershell
$previousDb = $env:DATABASE_URL
$previousFlag = $env:ASSETMOV_RUN_DB_INTEGRATION_TESTS
try {
    $env:DATABASE_URL = "mysql://root:@127.0.0.1:3306/assetmov_test"
    $env:ASSETMOV_RUN_DB_INTEGRATION_TESTS = "1"
    npm run db:deploy
    if ($LASTEXITCODE -ne 0) { throw "Test migration failed" }
    npm run db:seed:plans
    if ($LASTEXITCODE -ne 0) { throw "Test seeding failed" }
    npm run test:integration
    if ($LASTEXITCODE -ne 0) { throw "MySQL API acceptance failed" }
}
finally {
    if ($null -eq $previousDb) { Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue }
    else { $env:DATABASE_URL = $previousDb }
    if ($null -eq $previousFlag) { Remove-Item Env:ASSETMOV_RUN_DB_INTEGRATION_TESTS -ErrorAction SilentlyContinue }
    else { $env:ASSETMOV_RUN_DB_INTEGRATION_TESTS = $previousFlag }
}
```

**Important:** MySQL integration tests are intended to run on a disposable
`assetmov_test` database with a correct full migration history. A normal
run of `npm test` does **not** exercise these MySQL acceptance cases.

Only after tests pass and you have backed up the development `assetmov`
database should you run `npm run db:deploy` against that development DB.

### Committed source changes (not yet verified on WAMP)

1. Mobile workspace **drawer** with backdrop, escape dismissal and vertically
   scrolling menu. Existing narrow-screen data tables use scrollable, keyboard-
   focusable frames instead of expanding the page. Test 320px–1024px and zoom.
2. Permission-aware nav and direct-route guards. E.g. asset-only users see
   Overview, Asset Register and Transfers, not Employee/Location/Master Data.
   Scoped read-only location options allow asset/transfer users to choose
   locations without being granted location administration.
3. Company user creation asks for location **type**, then specific locations.
   Grants are validated in a tenant transaction and must not exceed the
   administrator's own manageable location scope.
4. Company Admin can reset an eligible non-owner user's password without
   email, requiring a reason. Password is scrypt-hashed, active sessions and
   recovery tokens revoked, audit written. Cannot reset self, company owner,
   or an identity used by multiple tenants. Password is transmitted privately
   by the administrator; a forced-change workflow and real email remain open.
5. Employee create/edit location-type selectors and append-only location
   movement history API. Relocation requires a reason and cannot silently
   move existing asset custody.
6. First-sheet XLSX import parser (modern browsers), CSV import, tenant-scoped
   existing-inventory-number preflight, row-level import errors and downloadable
   results CSV. Normal asset creation still enforces caps and conflicts.
7. Competing transfer dispatches now have a MySQL API acceptance case: one
   success, one conflict, never two concurrent transfers for one asset. Retryable
   transaction conflicts are handled with 409.
8. One additive migration:
   `20261112000100_employee_location_history` — a new history table; no
   existing Employee fields are rewritten.

### Security/release decisions

- **Last active company owner:** essential guard against locking a tenant out
  of its account. Existing code already rejects deactivation/role removal of
  the last owner; run a targeted browser/integration check.
- **Secure production attachments:** essential **before production**, not a
  blocker for local development. Current private MySQL-blob prototype is
  limited and lacks full streaming, content inspection, scalable storage
  lifecycle and recovery. Implement an isolated private object store with
  authenticated downloads and malware/metadata scanning before launch.
- **Linux MySQL case-sensitivity and migration replay:** essential before the
  first Linux deployment, because WAMP and Linux schema naming can differ.
  Rehearse fresh and upgrade migration paths against a disposable Linux MySQL.
- **Paddle sandbox and CI startup failures:** remain explicitly deferred by
  the owner; not passed.
- **Email verification delivery:** still unconfigured. Company-managed reset
  does **not** replace secure public reset and verified mailbox onboarding.
